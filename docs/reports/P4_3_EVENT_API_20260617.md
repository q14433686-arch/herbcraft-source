# P4.3 Event API — 2026-06-17

Status: implemented in source; built jars refreshed  
Baseline: Herbcraft `1.1.2` source line, `1.1.3` extension-planning milestone

## Goal

P4.3 adds public observational events for code addons.

The boundary remains:

```text
Events observe Herbcraft behavior.
Events do not mutate Herbcraft nutrition, pharmacology, knowledge, reload, or component results.
Content registration remains JSON-first.
Java write/registration APIs remain deferred.
```

## Implemented class

```text
core/src/main/java/com/herbcraft/api/HerbcraftEvents.java
```

The class uses Fabric's array-backed `Event` API.

## Events

### HERB_CONSUMED

```java
HerbcraftEvents.HERB_CONSUMED.register((player, item) -> { ... });
```

Fired after a full Herbcraft herb food has been consumed and processed.

The legacy `HerbConsumeEvents` class now delegates to this event and remains as a compatibility shim.

### NUTRITION_APPLIED

```java
HerbcraftEvents.NUTRITION_APPLIED.register((player, stack, itemId, profile) -> { ... });
```

Fired after a non-empty Herbcraft nutrition profile is applied to a player.

Notes:

- server-side only;
- `stack` is a copy;
- the event observes the applied profile and does not change it.

### INGREDIENT_DISCOVERED

```java
HerbcraftEvents.INGREDIENT_DISCOVERED.register((player, itemId, entryId) -> { ... });
```

Fired the first time a player tastes an Ingredient Codex / 食材录 entry.

Notes:

- namespace-aware external entry IDs are passed through `entryId`;
- repeated eating of an already tasted entry does not fire this event again.

### FOOD_NATURE_RESOLVED

```java
HerbcraftEvents.FOOD_NATURE_RESOLVED.register((player, stack, itemId, nature, result) -> { ... });
```

Fired after the food-nature bridge resolves pharmacology for an ordinary non-Herbcraft-herb food.

This is the event for addon authors who need to observe 药食志 / food-nature behavior.

Notes:

- server-side only;
- `stack` is a copy;
- `nature` is the explicit nature profile used;
- `result` is the already-computed pharmacology result;
- listeners cannot modify the result.

### EXTERNAL_DATA_RELOADED

```java
HerbcraftEvents.EXTERNAL_DATA_RELOADED.register((natureCount, nutritionCount, ingredientCount) -> { ... });
```

Fired after Herbcraft's reload-safe external data merge layer has reloaded and marked server-to-client data sync dirty.

The counts are current loaded totals after merge:

```text
natureProfileCount
nutritionProfileCount
ingredientEntryCount
```

## Why observational first

Mutation-capable events would need strict contracts for ordering, cancellation, sync, and conflict handling. P4.3 deliberately avoids that.

Addons can observe and react, but they should provide content through JSON and query current state through:

```text
com.herbcraft.api.HerbcraftDataAPI
```
